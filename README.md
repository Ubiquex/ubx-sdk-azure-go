# ubx-sdk-azure-go

Go bindings for the `hashicorp/azurerm` Terraform provider, generated by
[ubx](https://github.com/ubiquex/ubiquex) (`ubx sdk gen --lang go`). One
package per derived Azure service boundary (`kubernetes/`, `network/`,
`storage/`, ...), one file per resource type, all nested under
`azurerm/` — matches the real Terraform provider source,
`hashicorp/azurerm`, exactly.

Regenerated automatically on a weekly schedule (and via manual dispatch) by
`.github/workflows/version-watch.yml` — it checks the real
[Terraform Registry provider-versions API](https://registry.terraform.io/v1/providers/hashicorp/azurerm/versions)
for a newer `hashicorp/azurerm` release, and opens a PR with the
regenerated diff for review (never auto-merges). The version this repo was
last generated from is tracked in `VERSION`, not `.ubx/config.hcl` — this
repo carries no ubx stack/config of its own, only generated bindings.

Depends on the shared runtime, [ubx-sdk-go](https://github.com/ubiquex/ubx-sdk-go)
— a real, published, credential-free Go module dependency (no vendoring
needed, same as this SDK family's other Go repos).

Every file under a service directory except `doc.go` is generated — do not
hand-edit; re-run `ubx sdk gen` (or wait for the automated PR) after a
provider version bump.

**Final row of the original four-provider rollout (UBI-115, UBI-103) —
real findings, not assumed to match AWS/Google/Kubernetes' own:**

- **Real schema scale**: **1,103 resource types** for
  `hashicorp/azurerm@5.0.0` — the largest schema in this family after
  Google (1,330), well ahead of AWS (1,682 is still larger) and far
  ahead of Kubernetes (81). Not guessed: UBI-108's own lesson (Google's
  "likely 400-600" guess landed at 1,319) applied here too — checked
  directly, not estimated. 144 derived service packages.
- **The headline check this ticket asked for — the NestedType fix's
  generality claim — resolved with a definitive negative, not a "tested
  and passed" positive**: `hashicorp/azurerm@5.0.0` negotiates **tfplugin
  protocol v5**, not v6 (confirmed directly against the real launched
  binary's handshake, not assumed). `NestedType` — the Terraform Plugin
  Framework's structured/object-attribute wire encoding UBI-112's fix
  handles — is a field that exists only on `tfplugin6.Schema_Attribute`;
  `tfplugin5.Schema_Attribute` has no equivalent field at all. A v5
  session therefore cannot carry a `NestedType`-encoded attribute on the
  wire, structurally, regardless of whether azurerm's own resource
  implementations internally use the Plugin Framework. **The fix's
  generality claim is not exercised by this provider at this version —
  not because azurerm avoided the shape Kubernetes hit, but because
  azurerm's wire protocol makes that shape impossible to observe from
  the client side.** This is a different, more fundamental finding than
  "checked and found zero real instances" (Google's version-suffix
  check, below) — there is no NestedType risk surface here at all, full
  stop, until/unless azurerm's provider server ever registers v6.
- **The compiler-crash-class issue (UBI-98)** — confirmed absent: largest
  generated file is `azurerm/kubernetes/cluster.go` at 1,057 lines,
  nowhere near the pathological ~250,000-line scale that hit
  `aws_wafv2_web_acl_rule`.
- **The sibling-`_config` collision class (UBI-96/108)** — checked for
  real against the full real wire-name set (every `<type>` paired against
  `<type>_config`), confirmed absent: zero collision candidates, `go
  build ./...`/`go vet ./...` clean across the full 1,103-type tree.
- **The bare-version-suffix-filename class (UBI-112)** — checked for
  real: azurerm has exactly 3 version-suffixed wire names
  (`azurerm_app_service_environment_v3`,
  `azurerm_monitor_scheduled_query_rules_alert_v2`,
  `azurerm_stream_analytics_stream_input_eventhub_v2`), and all three
  already carry more than one token ahead of the version marker — same
  shape as Google's one `google_apigee_security_profile_v2` instance, so
  none hit the fold's narrow bare-marker trigger. Zero bare `vN.go`
  filenames in the real generated tree. No Azure-specific collision class
  found beyond this.
- **Zero `ubiquex` source changes needed this session** — unlike
  Kubernetes (UBI-112), which needed two real fixes at the source, Azure's
  real schema hit no new schema-shape class at all. Full rollout summary:
  AWS/Google/Kubernetes/Azure are now real and live in Go, TS, and Python
  (twelve repos total) — the original four-provider rollout plan is
  complete.
